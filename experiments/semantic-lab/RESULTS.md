# 首次本机实测 · 2026-10-16

三个模型均已使用固定本地权重，经真实 CPU 推理和 HTTP 接口跑通。以下是人工编写的六条样例，每个模型各跑一次；样本很少，供观察误判，不是准确率评测。完整文本、revision、分数和耗时见 [原始结果](results/benchmark.json)。

| 合成场景 | COLD 冒犯分数 | Horizon toxicity | MiniLM 最高相关标签与分数 |
| --- | --- | --- | --- |
| 正常讨论 | 0.005 | 0.006 | 人身攻击 0.830 |
| 直接攻击 | 0.967 | 0.701 | 人身攻击 0.902 |
| 引用并反对辱骂 | 0.975 | 0.648 | 人身攻击 0.986 |
| 反讽 | 0.020 | 0.081 | 人身攻击 0.779 |
| 体育话题 | 0.004 | 0.008 | 体育讨论 0.949 |
| 负面情绪 | 0.006 | 0.036 | 招聘推广 0.956 |

COLD 和 Horizon 的输出来自不同任务、不同训练数据，不能横向平均。MiniLM 是候选话题相关度；默认按每个标签的 entailment / contradiction 独立归一化，不保证各项相加为 1，也不是攻击性概率。

这轮最明显的边界：COLD 将“引用辱骂并明确反对它”判为高冒犯，反讽样例则给出低分；Horizon 的直接攻击样例约 0.70，说明试验台默认 0.80 阈值会漏过它；MiniLM 将普通讨论、负面情绪误判为其他标签。阈值滑块只演示折叠，不是已经校准的推荐值。

另外对普通感谢教程、人身攻击、体育讨论三个合成句，预先选定三套中英文标签／模板进行 [9 次对照](results/template-comparison.json)。三套都识别了攻击和体育样例，也都误判了普通感谢句。没有据此反复调参，暂不推荐任何一套作为自动屏蔽默认方案。

真实浏览器另对攻击句追加“仅用于本地模型测试的合成句”后触发了新推理：COLD 冒犯分数降到约 0.134，Horizon 约 0.639。这也提示上下文措辞会强烈影响分数，不能仅看一条测试成功就启用自动隐藏。

本机这批短文本的单次推理约 19–100 ms（不含加载和缓存命中）；首次启动库导入及模型加载需要数秒至数十秒，切换模型也有加载开销。长文本、多标签、其他电脑会不同。服务默认只驻留一个模型，可用“释放”清理内存。

适合的后续用法：COLD 和 Horizon 作为可展开的提示或规则条件，引用内容独立处理；MiniLM 继续试验话题标签，先观察结果。插件的实验性接入默认关闭，需手动部署、授权后启用。试验台输入不落盘；此处 JSON 仅是人工合成测试记录。
